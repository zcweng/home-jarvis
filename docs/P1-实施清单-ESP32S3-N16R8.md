# P1 实施清单（按你的硬件定版）

> 基于你确认的三点：①小爱音箱＝第一代小米AI音箱 ②ESP32-S3-N16R8 ③家电全 WiFi 米家设备
> 配套总方案：`docs/家庭智能管家-技术方案.md`

---

## 0. 三个答案对方案的影响

| 硬件 | 原假设 | 确认结果 | 结论 |
|---|---|---|---|
| 小爱音箱 | 可能是 LX06/OH2P（可刷机） | **第一代小米AI音箱（2017）** | 刷机路线**彻底出局**（Open-XiaoAI 只支持 LX06/OH2P，且已停维护）。它退居"音乐播放器 + 闹钟"，不进对话链路 |
| ESP32 | 可能不够用 | **N16R8 = 16MB Flash + 8MB PSRAM** | 满足 ESP-SR AFE 的硬件门槛（S3 + PSRAM）。但**裸开发板没有麦克风、没有功放、没有喇叭** → 需要采购 ¥90~130 |
| 米家设备 | 协议混杂 | **全 WiFi** | 这是米家集成覆盖最好的一类；它不支持蓝牙/红外/虚拟设备的短板**正好全部避开**。中枢网关从"建议买"降级为"可选" |

一句话：**你的板子够用，缺的只是外围器件；小爱帮不上忙，但也不需要它帮忙。**

## 2. 接线表（沿用官方 `bread-compact-wifi` 默认管脚）

| 信号 | ESP32-S3 | 接到 |
|---|---|---|
| 麦克风 WS | GPIO4 | INMP441 ×2 的 WS（并联） |
| 麦克风 SCK | GPIO5 | INMP441 ×2 的 SCK（并联） |
| 麦克风 DIN | GPIO6 | INMP441 ×2 的 SD（并联） |
| 喇叭 BCLK | GPIO15 | MAX98357A 的 BCLK |
| 喇叭 LRCK | GPIO16 | MAX98357A 的 LRC |
| 喇叭 DOUT | GPIO7 | MAX98357A 的 DIN |
| 按键 | GPIO0 | 板载 BOOT，单击=说话/打断，长按=复位 |

（以上来自 `main/boards/bread-compact-wifi/config.h`，采样率：麦克风 16kHz、喇叭 24kHz，**两者不同，别写成一样**）

六个必须注意的硬件坑：

1. **INMP441 的 L/R 引脚不能悬空**：一个接 GND（左声道）、一个接 VCC（右声道），否则 I2S 帧里两声道数据相同或全零 —— 这是 DIY 最大翻车点
2. **N16R8 的 Octal PSRAM 占用 GPIO33~37**，这几个脚不能用
3. 麦克风和喇叭至少要隔着 ≥5cm、朝向相反，物理隔离省下来的 AEC 压力比算法优化管用
4. MAX98357A 用 5V 供电更响，但 SD 模式引脚接法决定增益档位，先接默认再调
5. 功放和 S3 若共用 5V，喇叭一响电压就掉 → 加大电容，或干脆两路供电
6. 先用万用表确认 INMP441 的 VDD 是 3.3V（它是 3.3V 器件，5V 会烧）

## 3. 固件：分两段走，别一步到位

### 3.1 第一段：单麦跑通（半天）

- 编译环境要求 **ESP-IDF ≥ v6.0.1**（官方明确 ESP-IDF 5.x 已不支持）
- 直接用官方现成板型 `bread-compact-wifi`（单 INMP441 + MAX98357 + 无 AEC），**一个字的代码都不用改**
- 你的板子是 16MB Flash，需在 `sdkconfig` 里改 `CONFIG_ESPTOOLPY_FLASHSIZE_16MB=y` 并选对应分区表
- 编译：`python scripts/build.py bread-compact-wifi`
- 烧完配网（开机热点或 BluFi），默认连你自己的服务端地址
- **验收**：说一句"你好小智"+问题，能听到回答 → 说明"耳朵-大脑-嘴"整条链路通了

### 3.2 第二段：要不要"可打断"

固件里有两套音频引擎：`lite_audio_engine`（无 AEC，单麦够用）和 `afe_audio_engine`（ESP-SR AFE，含 AEC/降噪/VAD，**需要一路"回采参考信号"**）。参考信号的两种搞法：

| 做法 | 成本 | 效果 | 难度 |
|---|---|---|---|
| a) 软件回采：把即将播放的 PCM 当 ref 通道喂给 AFE | ¥0 | 能打断，回声残留较多 | 中，要补偿 DAC→喇叭的时延 |
| b) 硬件回采：换 ESP32-S3-BOX-3（ES7210 采集 + ES8311 回采） | ¥300+ | 接近商业音箱 | 低，官方板型现成 |

**决策点**：先用 §3.1 单麦跑一周，如果"不能打断"确实影响使用（大概率会），再花 ¥300 上 BOX-3。**不要一上来就啃软件回采**，那是最容易十天半个月没进展的坑。

自定义板子的硬性规矩（官方警告）：**必须新建 `main/boards/suke3-home-s3/` 目录，不许覆盖 `bread-compact-wifi`**，否则将来 OTA 升级会被官方标准固件覆盖。`config.json` 里写 `"type": "suke3-home-s3"`、`"target": "esp32s3"`，并把 16MB Flash 与自定义分区表写进 `sdkconfig_append`。

## 4. MacMini 部署（Docker）

### 4.1 端口规划（先规划，免得到处撞车）

| 服务 | 端口 | 说明 |
|---|---|---|
| Home Assistant | 8123 | host 网络 |
| 小智服务端 WebSocket | 8000 | ESP32 连这个 |
| 小智管理后台 | 8002 | 浏览器配置用 |
| OTA 接口 | 8003 | 固件检查更新 |
| 你的测试页 | 8006 | 没硬件时当麦克风用 |

### 4.2 七步

1. MacMini 装 Docker Desktop 或 OrbStack（M1 用 arm64 镜像）
2. HA 用官方镜像 + `network_mode: host` + 挂载 `./ha-config:/config`，跑起来后访问 `:8123`
3. HA 里装**小米官方米家集成**（HACS 安装，或 `git clone` 后跑 `install.sh`）：要求 HA Core ≥ 2024.4.4、HAOS ≥ 13.0
4. 添加集成 → OAuth 登录小米账号（密码不进 HA）→ **选对地区**（数据按地区隔离，选错看不到设备）→ 勾选设备
5. 在 HA 里生成**长期访问令牌**，给服务端的工具层用
6. 部署 `xiaozhi-esp32-server` 全模块（官方 `docs/Deployment_all.md`；参考配置 4 核 8G，M1 16G 绰绰有余）
7. 在智控台里配：ASR = **FunASR（本地免费）**、LLM = **DeepSeek**（`api.deepseek.com`，`deepseek-flash`）、TTS 先用 **EdgeTTS** 跑通，稳定后再换火山流式压延迟

> 配置文件的准确路径与字段以官方 `Deployment_all.md` 为准（本项目迭代快，别照抄网上旧教程）。

### 4.3 先别开的两个开关

- **米家集成的"局域网控制"**：官方文档明确"可能会引起一些异常，我们建议不要使用该功能"。全 WiFi 场景确实能占便宜，但先跑通云端模式再试
- 外部 API 的"推理型模型"：控制链路里用 flash 类快模型，别把思考模型塞进来

## 5. 家电接入：全 WiFi 的三个红利

1. **覆盖率最高**：米家集成对 WiFi 设备支持最全，云端 MQTT 订阅让状态变化秒推，不用轮询
2. **中枢网关不是必需品**：全 WiFi 设备可以直接走云（延迟 200~800ms 估）。等哪天觉得"灯慢半拍"，再花 ¥250 买中枢网关换本地控制
3. **别名表可以先做小**：先从 3 个房间 × 5 个高频设备开始，别一次把 50 个实体塞给模型

工具契约沿用总方案 §5.4 的 5 个：`control / query / scene / announce / timer`。危险设备（门锁、大功率插座、燃气）二次确认 + 声纹权限。

## 6. 验收清单

### P0（硬件没到货也能做，1~2 天）

- [ ] HA 起来，米家集成登录成功，能列出你家设备
- [ ] 用 HA 界面手动开关客厅灯成功（**先证明设备层通，再谈语音**）
- [ ] 小智服务端起来，`http://127.0.0.1:8006/index.html` 测试页能语音对话
- [ ] 说"打开客厅灯"，灯亮（工具调用通）
- [ ] 说"调到 20%"→"再暗一点"，3 轮指代正确
- [ ] 跑 `performance_tester.py`，记下 ASR/LLM/TTS 各自耗时，作为基线

### P1（硬件到货，1 天）

- [ ] 固件烧写成功，配网成功，设备在线
- [ ] 5 米内唤醒率 ≥ 90%（安静）/ ≥ 70%（开电视）
- [ ] 端到端首字 ≤ 2.0s（10 次实测取中位数）
- [ ] 单麦阶段：按键打断可用
- [ ] 连续对话窗口：播报完 6s 内直接说"再暗一点"，不用重复唤醒词

## 7. 你这个组合最可能踩的 6 个坑

| # | 坑 | 现象 | 处理 |
|---|---|---|---|
| 1 | INMP441 的 L/R 悬空 | 录音全静音/单声道混叠 | L 接 GND、R 接 VCC |
| 2 | 麦克风 16k / 喇叭 24k 写成同一个采样率 | 声音变调、识别率暴跌 | 固件里两个宏分别定义 |
| 3 | 覆盖官方 board 目录 | 某次 OTA 后固件被官方版刷掉 | 新建独立 board 目录 + 唯一 type |
| 4 | 功放与开发板共用 USB 供电 | 一说话就重启/爆音 | 独立 5V + 1000µF 去耦 |
| 5 | 米家集成 token 明文存 HA 配置 | 配置泄露=小米账号被冒用 | MacMini 开 FileVault，配置目录单独加密备份，HA 不暴露公网（用 Tailscale） |
| 6 | 想一步做到"可打断" | 卡在 AEC 上半个月无进展 | 先单麦跑通价值，再决定买 BOX-3 |

补充一条非技术坑：**第一代小米AI音箱进不了这条链路**（没有开放麦克风流，也不是能刷机的 LX06/OH2P）。它继续当音乐播放器和闹钟，属于"分工"，不是"浪费"。如果你确实想让它播报天气预报之类的，社区有走米家云端 MiNA 接口的 TTS 方案（xiaogpt 的思路），代码量约 50 行，作为 P3 锦上添花，别放进核心链路。

## 8. 48 小时行动顺序

**Day 1 上午**：下单采购件 → MacMini 装 Docker → HA 起来 → 米家集成登录 → **手动点亮客厅灯**
**Day 1 下午**：部署小智服务端 → 测试页跑通对话 → 配 3 个别名 → **语音点亮客厅灯**
**Day 1 晚上**：跑性能测试，记下延迟基线；把"再暗一点/关掉它"的指代做通
**Day 2**：接线 → 烧 `bread-compact-wifi` 固件 → 配网 → 端点上线 → 5 米唤醒测试

Day 1 结束时你应该已经有一个"能用"的语音管家（只是没有常开的耳朵）；Day 2 才是把它搬进客厅。
