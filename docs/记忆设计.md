## 记忆架构链路
用户输入 → 记忆路由控制器
    ↓
1. 加载【会话记忆】（当前会话上下文、状态）
2. 触发召回：向【永久记忆】检索相关片段
3. 全部记忆送入 记忆筛选器（重排、去重、过滤噪声、控制token）
4. 拼装Prompt → LLM思考/工具调用
5. 思考输出后 → 记忆写入策略：
   - 新消息直接写入会话记忆
   - 判定为重要情景 → 异步固化到永久记忆（向量化+时序标签）
   - 判定为事实/规则变更 → 异步固化到永久记忆（向量化+时序标签）

### 核心组件清单

1. **记忆路由控制器**：统一入口，负责召回、写入、过期
2. **记忆分类器（LLM / 小模型）**：判断一条新信息该进哪一层、打分重要性
3. **检索模块**：混合检索（向量相似度 + 元数据过滤 + 关键词）
4. **记忆衰减 & 热度管理器**：长期记忆自动降权
5. **记忆压缩 / 摘要器**：长对话自动摘要，防止向量库塞满原始文本
6. **记忆校验器（永久记忆专用）**：事实冲突检测
7. **记忆遗忘接口**：支持主动遗忘、擦除

## 存储结构示例（Redis Hash / 内存对象）
{
    "memory_id": "mem_xxx",
    "user_id": "u_1001",
    "content":"用户上周说不吃香菜",
    "summary": "用户饮食偏好：拒绝香菜",
    "embedding": [...],
    "importance": 0.72,
    "heat_score": 0.65,
    "tags": ["preference","food"],
    "created_at": 1720000000,
    "is_archived": false
}

衰减公式:

heat = importance * e^(-lambda * DeltaT) * recall_boost

- lambda：衰减系数，控制遗忘速度；
- DeltaT：距离上次召回的时间；
- recall_boost：每次被检索命中，热度加分（经常用到的记忆不容易忘）；

生命周期流转：

1. 会话记忆里的摘要，经过分类器打分，重要性 > 阈值才写入永久记忆；
2. 检索时：向量相似度 + heat_score 混合排序；
3. 热度持续低于阈值 → 标记归档（is_archived=true），默认召回不读取；
4. 归档记忆不是删除，可通过 “深度回忆” 模式手动召回；
5. 支持记忆合并：相似语义片段自动合并，减少冗余。

> 
> 适合存：用户随口说的偏好、历史任务、上次沟通的情景、临时约定。



## 记忆召回流程（怎么把记忆拿出来用）

召回是最容易踩坑的地方：**召回太多 → token 爆炸，召回太少 → 失忆**
标准召回 Pipeline：

1. 拿到用户 query，生成 query embedding；
2. 并行检索：
   - 永久记忆：按 user_id + 标签过滤 + 向量检索，优先召回事实；
   - 长期记忆：向量相似度 + heat 热度综合排序，过滤已归档；
3. 重排（Rerank）：CrossEncoder / LLM 打分，剔除无关；
4. 配额控制：设置总记忆 token 上限（比如 800~1500 token）；
5. 拼接顺序：永久事实（靠前）→ 高热度长期记忆 → 短期上下文；
6. 送入 LLM。
